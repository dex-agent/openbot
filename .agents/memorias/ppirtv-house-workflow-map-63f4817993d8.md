# ppirtv-house-workflow-map

Espelho da auto-memory do host ZCode (arquivo ppirtv-house-workflow-map.md, tipo feedback).

The house PPIRTV workflow has fixed skill owners per phase and is

The base workflow is PPIRTV: P🧠 Pensamentos → P🗂️ Planejamento → I🛠️ Implementação → R🔎 Revisão → T🧪 Teste → V✅ Validação. Its owners are named skills, not ad-hoc steps: `$reuniao` → `$sprinter` → `$mapeador-implementacao` ↔ `$revisor-codigo` ↔ `$tio-testador` ↔ `$validador-pronto`. `$ancora-fluxo` (with `$auto-fluxo-flow`) orchestrates; `$chato` is the commander; `$questionador`, `$critico-cetico`, `$entrevista-me`, `$burrinha`, `$karpathy-guidelines` stay live without blocking execution; `$garimpeiro` + `$estacionamento` stay active for the whole block.

Canonical memories: `global/memorias/fluxo-ppirtv-ancora-fluxo.md`, `modo-de-trabalho-preferido-do-dono-fluxo-ppirtv-com-b6058d1b60bd.md`, `padrao-do-dono-ao-ativar-o-fluxo-visual-ppirtv-anco-096294c0bf75.md`, and `fluxo-ppi-orquestracao-com-chato-lider-e-fechamento-1bd33aaced93.md` (the last supersedes `fluxo-pi-orquestracao-chato-lider.md`).

**Why:** the owner asked twice, bluntly, whether the work followed the Dex ecosystem and PPIRTV; designing a team without these owners was rejected.

**How to apply:** locate the profile first with `$dex-locate-memories` (route: Finder or `rg --hidden --no-ignore` over the vault), open the canonical memory, then map each phase to its owner before writing any charter or plan. Close every block with phase run visually, one single recommended next step, `$dex-fechamento-projeto-atualizado`, and the memory ritual. See [[equipe-dev-team-charter]].
